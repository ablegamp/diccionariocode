Git y GitHub: Guía Completa para Principiantes

28 de diciembre, 2023 • Por Ana Martín • 12 min de lectura

Git es el sistema de control de versiones más popular del mundo. En esta guía aprenderás desde los conceptos básicos hasta técnicas avanzadas para colaborar efectivamente en proyectos.

¿Qué es Git?

Git es un sistema de control de versiones distribuido que permite rastrear cambios en archivos y coordinar el trabajo entre múltiples desarrolladores. Cada desarrollador tiene una copia completa del historial del proyecto.

Comandos Esenciales

# Inicializar un repositorio
git init

# Clonar un repositorio
git clone https://github.com/usuario/repo.git

# Agregar cambios al staging area
git add .
git add archivo.js

# Hacer un commit
git commit -m "Mensaje descriptivo"

# Ver el estado del repositorio
git status

# Ver el historial de commits
git log

Trabajar con Ramas

Las ramas permiten desarrollar características de forma aislada sin afectar el código principal: 

# Crear y cambiar a una nueva rama
git checkout -b nueva-caracteristica

# Cambiar entre ramas
git checkout main
git checkout nueva-caracteristica

# Fusionar ramas
git checkout main
git merge nueva-caracteristica

# Eliminar rama
git branch -d nueva-caracteristica

GitHub: Colaboración en la Nube

GitHub es una plataforma que aloja repositorios Git y facilita la colaboración: 

# Conectar repositorio local con GitHub
git remote add origin https://github.com/usuario/repo.git

# Subir cambios a GitHub
git push origin main

# Bajar cambios de GitHub
git pull origin main

# Ver repositorios remotos
git remote -v

Flujo de Trabajo Recomendado

  1. Crea una rama para cada nueva característica
  2. Haz commits frecuentes con mensajes descriptivos
  3. Sube tu rama a GitHub
  4. Abre un Pull Request para revisión
  5. Fusiona después de la aprobación
  6. Elimina la rama después del merge

Consejos y Mejores Prácticas

Commits Atómicos

Cada commit debe representar un cambio lógico único.

Mensajes Descriptivos

Usa mensajes que expliquen qué y por qué cambió algo.

Pull Requests

Siempre usa PRs para revisar código antes del merge.

Dominar Git y GitHub es esencial para cualquier desarrollador moderno. Con práctica, estos comandos se volverán segunda naturaleza y mejorarán significativamente tu flujo de trabajo.
